# Rust Unsafe Block Detector

## Detection Prompt

```
Analyze Rust code for unsafe block misuse. Look for:

1. Unsafe Functions and Blocks:
   - unsafe { ... } without safety documentation comments (// SAFETY:)
   - unsafe fn without explaining safety invariants
   - Large unsafe blocks (more than a few lines without justification)
   - Unsafe blocks in library public API

2. Memory Safety Violations:
   - std::mem::transmute with unvalidated types
   - Raw pointer dereference (*const, *mut) without null/bounds checks
   - std::mem::uninitialized / MaybeUninit misuse
   - Manually implementing Send/Sync on types containing raw pointers

3. FFI / C Interop Issues:
   - extern "C" functions with unvalidated parameters from C
   - CString / CStr creation without null terminator validation
   - Casting between fn pointers and data pointers
   - Calling C functions with user-controlled data without length validation

4. Concurrency Unsafety:
   - UnsafeCell misuse for shared mutable state
   - Incorrect atomic ordering (Acquire/Release instead of SeqCst)
   - Mutex poisoning not handled

Code context:
{code}
```

## Validation Prompt

```
Rust unsafe at {file}:{line}. Is there safety documentation? Are invariants actually maintained? Is the unsafe justified by performance or FFI requirements?

Respond with JSON: {"confirmed": true|false, "confidence": 0.0-1.0, "reason": "..."}
```

## FP Heuristics

- Well-documented unsafe with valid safety invariants (// SAFETY: ...)
- Standard library internals (std::vec, std::collections) using unsafe correctly
- FFI bindings generated by bindgen/cbindgen (auto-generated, usually safe)
- Test code with intentional unsafe for verification
